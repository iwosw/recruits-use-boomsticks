## Native multi-step loading chains

`ArtilleryReloadProtocol` holds the bytecode-confirmed loading chain per weapon; `ArtilleryReloadStep` describes one step as accepted components, native NBT writes, cost, lore, and sound, and `ArtilleryComponentAccess` resolves tag-, identity-, or bare-hand-matched components and pays their native cost. **Every one of the seventeen enabled gameplay weapons now has a chain**; the per-weapon table lives in `docs/compat/artillery-addon-1.14.0-api.md`. A weapon absent from the protocol would keep the previous single-transaction reload.

Four constraints were learned from runtime failures and must not be re-broken:

- a recruit's equipment slots are backed by inventory slots (`AbstractInventoryEntity.getInventorySlotIndex`), so a borrowed tool is moved between inventory slots, never copied into the equipment slot;
- a consumed component is split one at a time into the off hand; shuttling a whole ammunition stack in and out of the off hand loses rounds (it cost the Chu Ko Nu magazine one arrow per run);
- a chain that already spent components must be allowed to finish, so `RecruitBoomstickAttackGoal` treats an in-progress chain as ammo-available;
- a step's native writes must land exactly on the profile's loaded payload, so `ArtilleryReloadProtocolTest` walks every chain and asserts `ArtilleryNativeState.isLoaded`. Correcting the chains also corrected four profiles: Carbine and Harquebus load at native `stage=3.0`, Chu Ko Nu's magazine is the native eight rounds, Handgonne and Tiller Gun carry the native `ammo=0.0`/`loaded` markers, and the Noble Handgonne Arrow branch has no `loaded` flag.

Ammunition per reload comes from the chain itself (`ArtilleryReloadProtocol.ammoConsumed`), not from `projectileCount`: the Hand Cannon's native volley costs one ball, and only Chu Ko Nu spends one arrow per magazine round.

The native procedures keep the weapon in the off hand and the tool in the main hand. Recruits require the weapon in the main hand, so the hands are mirrored deliberately; everything else matches the native chain.

## Artillery runtime artifact switch

`build.gradle` selects the Artillery Addon runtime file through the optional `artillery` project property:

- default — file `7455014` (1.11), the pinned server-safe artifact every GameTest claim is validated against. It does not register Tiller Gun, Noble Handgonne, Hackbut, or Double Barrel Gonne, so those tests fail closed on their registry prerequisites.
- `-Partillery=1.14` — file `8325660` (1.14.0), which registers all seventeen guns in `#artillery:guns`. It is **client-only**: its automatic subscriber loads the client-only `ClientLevel` class, so a dedicated server aborts during startup. `runGameTestServer` therefore refuses this property with an explicit error rather than producing a misleading failure.

Use `./gradlew runClient -Partillery=1.14` for manual in-game checks of the four dependency-gated profiles. Automated proof stays on the default file until an upstream artifact registers those items and loads on a dedicated server.
